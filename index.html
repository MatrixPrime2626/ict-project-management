    About this page

    This is the UX/UI prototype and design reference for the Digital Front Door. It shows the screens, wording, validation and data alerts the team agreed. It is not the live service.

    Use Viewing as in the header to switch between the Requester journey and the Digital Project Manager workspace (NFR3). On the saved version, only the page owner and Editors get the Digital Project Manager view. The six requests marked as sample data are synthetic.

    Version 4 (Sprint 2): the pipeline can be filtered by keyword, benefit category, directorate and priority tier, with Clear filters to restore the full view (CW02F06-20). The Digital Project Manager can send an unclear request back to the requester under the same reference; the requester answers in My requests, and anything waiting 5 days or more is flagged as overdue (CW02F06-21).

    The live build runs inside LSBU's standard Microsoft 365 tenant (NFR1): a Power Apps canvas app writing to the Opportunity_Intake SharePoint list, with Power Automate sending receipts and status alerts. Requester name and email come from Microsoft Entra ID sign-in, so the form does not ask for them.

    Request

    Triage scores

    Score each PID criterion from 1 to 5. Complexity and resource requirement lower the priority.

    How the score works: Strategic alignment 30%, Benefit potential 25%, Speed to value 15%, Complexity 15% and Resource requirement 15% (the last two inverted), giving 0 to 100. High is 75 or more, Medium 50 to 74, Low below 50. These are the team's proposed default weights; under FR7 an administrator can change them.
